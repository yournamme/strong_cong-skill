# 开发选题路由（AI 帮你选集）

用户有两条互相喂的副业线：**AI 开发**（小工具 / 小游戏，可含软硬结合）和 **AI 自媒体**。开发产物变成内容，内容反馈变成下一个开发灵感。用户最大的卡点不是"会不会做"，而是"**不知道该做什么**"。

这个 skill 的职责边界很清楚：**只负责选出做什么，不负责怎么做。** 拍板完成即交棒。

## 用户画像（选题时必须记住）

- **底子**：电子信息工程——嵌入式、单片机、电赛、硬件调试；同时会 AI agent、skill、自动化脚本。
- **硬件立场**：会硬件但不算强。硬件项目**可以做**，但只在"确实有用且做得动"时才推，不占主导。
- **排序取向**：**好出内容、涨粉快 > 做起来快、有成就感 > 能赚钱 > 攒作品集**。所以同等条件下，永远优先推"过程本身就好看、好讲、有钩子"的选题。

---

## 第 0 步：先读盘（必做，别跳）

在采集任何新灵感前，先搞清楚现状，否则会推重复选题。

1. **定位 Obsidian 库根目录**。用户环境可直接读本地文件（Claude Code / Cowork）。按顺序找：
   - 当前工作目录或用户已提过的路径
   - 用 glob 找 `**/01 Projects/` 或 `**/*.obsidian/` 定位库根
   - 找不到就问一句："你的 Obsidian 库在哪个路径？"——只问这一次，拿到后记住，别反复问
2. **读 `02 Areas/内容创作/开发选题/开发选题池.md`**（不存在则待第 4 步创建）。
   - 提取所有已存在条目的名字和状态，本轮候选**必须去重**
   - 状态为 `⏳ 开发中` 的条目，先问："上次那个 X 还在做吗？要不要先收尾？"——避免摊子越铺越多
3. **扫一眼最近动向**：按修改时间列出库里最近 2 周改过的笔记（`ls -lt` 或等价方式），这些是用户当前真正在关心的东西，权重高于陈年老笔记。

读盘结果不用长篇汇报，一两句话带过即可，比如"选题池里已有 6 条，2 条开发中；最近你在折腾 X 和 Y"。

---

## 第 1 步：喂料（采集灵感源）

四个源，按优先级采。**先收"真"，不收"好"**——真 = 有出处，能指到某条笔记或某件用户真做过的事。

### 源 1：Obsidian 素材池（最优先）

具体动作，不要只是"搜一下"：

- 读 `选题池.md`、`制作小工具.md`（若存在）里的全部条目
- 遍历 `01 Projects/备战电赛/`、`01 Projects/AI与自动化/` 下的笔记
- 全库 grep 这些关键词，抓出散落的念头：
  `想做`、`要是有个`、`TODO`、`待办`、`踩坑`、`太麻烦`、`手动`、`每次都`、`idea`、`灵感`
- 每条灵感记下**来源笔记的文件名**，候选卡片里要写出来

### 源 2：用户自己的重复动作与麻烦（真实需求，含金量最高）

- 从笔记里的"踩坑""每次都要"记录中直接提取
- 若素材不够，问一句（**只问一句，别连环问**）："最近哪件事你重复做过三次以上、每次都觉得烦？"

### 源 3：市场参考（验证需求存在，不是抄）

- 联网搜同类品：独立开发者近期上线的小工具 / 小游戏、GitHub 近期涨星的轻量项目、相关话题下播放量高的内容
- 用法是"**已验证的品类 × 只有我这经历的人才想得出的角度**"。例如品类是"番茄钟"，角度是"用单片机做个实体的、按下去有物理咔哒声的番茄钟"
- 禁止直接照搬一个已经很成熟的产品当候选

### 源 4：内容反馈（闭环回流）

- 自媒体评论区、私信、后台数据里观众反复问的、想要的
- "要是能做成 XX 就好了" → 直接就是下一个候选

**喂料产出**：一份原始灵感清单，能收多少收多少，此时不评判好坏。

---

## 第 2 步：过滤（三条硬门槛 + 加权排序）

### 三条硬门槛（一票否决，不打折）

1. **真实**：解决一个真实存在的小麻烦，能指出出处（某条笔记 / 某次经历 / 某条评论）。想象出来的需求直接砍。
2. **做得动**：**2 周内能出 MVP**，AI 兜底也算数。超出的砍进"以后再做"。
3. **有得发**：过程或成品**至少能变成 1 条内容**。变不成内容的，对这个闭环没价值，砍。

三条全过 → 进入排序。缺任意一条 → 不进候选，但记进选题池的"待定"区（可能以后条件变了就能做）。

### 加权排序（决定 3-5 个候选的先后顺序）

每项按 0 / 1 / 2 打分，加权求和。**内容势能权重最高，这是用户的选择。**

| 维度 | 权重 | 2 分的样子 |
|---|---|---|
| 内容势能 | ×3 | 有视觉冲击或反差钩子，标题现在就能想出来，能拆成系列 |
| 上手速度 | ×2 | 三天内能跑出个能看的东西 |
| 差异化（只有我能做） | ×2 | 用到了嵌入式/电赛/硬件调试这类别人没有的经历 |
| 变现或积累 | ×1 | 能收费、能进作品集、能沉淀成可复用模块 |
| 底子匹配 | ×1 | 用的都是熟技术，学习成本低 |

总分上限 18。按总分从高到低排候选顺序，分数写进卡片。

### 硬件项目的额外条款

软硬结合项目**可以进候选**，但必须同时满足，否则降级为纯软件版本：

- 所需器件是**手上已有的**，或一周内能到货且花费在可接受范围
- **软件部分能独立跑通**——万一硬件卡住，还能出一个纯软件的 MVP 保底
- 明确说清楚"硬件在这里带来了什么软件做不到的东西"（通常是内容上的实物冲击力）

### 反模式（不要推给用户的选题）

- 需要长期在线维护的服务端产品（成本和心智负担太重）
- 需要冷启动用户量才成立的社交/社区类
- 依赖爬取他人平台数据、有合规风险的
- 功能清单超过五条的"平台级"设想
- 已经有成熟免费方案、且用户做不出差异化的

### 过滤纪律

- 宁可给 3 个有钩子的，不给 8 个平庸的
- 每条候选必须能回答"为什么是它"，不能只列名字
- **别捧场**：每张卡片必须写一句真实的反对意见

---

## 第 3 步：候选产出（3-5 个，按分数排序）

每个候选用这个格式，逐条填满，不留空：

```markdown
### 候选 N：<名字>  ·  <总分>/18

- **做什么**：一句人话，不用术语
- **给谁用**：越具体越好（"我自己 + 备战电赛的大二学生"，而不是"开发者"）
- **解决什么麻烦**：那个真实的小麻烦 + 出处（来自哪条笔记/哪次经历）
- **MVP 边界**：砍到不能再砍的最小功能，以及明确不做什么
- **内容钩子**：第一条内容的标题现在就写出来，并说清楚它的看点是什么
- **怎么算有价值**：变现 / 作品集 / 技术沉淀，说清楚哪一种
- **为什么是我**：用上了哪段独有经历（嵌入式、电赛、硬件、agent）
- **风险与未知**：最可能卡住的那一步是什么
- **一句反对意见**：这个选题最站不住脚的地方
- **打分**：内容 x/2 · 速度 x/2 · 差异化 x/2 · 价值 x/2 · 底子 x/2
```

候选列完后，加一行**默认推荐**："如果懒得选，我建议 N，因为……"（一句话，不超过两行）。

---

## 第 4 步：拍板（用户的事，但别让他卡住）

- 一次性把候选全列出来，让用户选 1 个。**不要连环提问。**
- 用户说"都行 / 你定" → 直接采用默认推荐，说清理由，不再追问
- 用户犹豫超过一轮 → 收敛成二选一："A 更好出内容，B 更快见效，选哪个？"
- 用户全否了 → 不要硬凑第二批。问一句"是哪里不对——太难、没意思、还是没用？"，按答案回第 1 步换源头重采

拍板后立刻写进 `开发选题池.md`，状态 `✅ 已拍板`，并记录日期与三条门槛/打分情况。

---

## 第 5 步：接棒（交给开发工作流）

拍板即为本 skill 收工。交出一张**交接卡**，内容就是候选卡片本身加上这三行：

- 目标 MVP 边界（第 3 步里的原文）
- 第一条内容的标题（第 3 步里的原文）
- 最可能卡住的那一步

然后明确说：下一步把这张交接卡交给 **planning-with-doc / vibe_coding** 走"方案讨论 → 任务拆解 → 开发"。

**闭环提醒**：开发完成后，回到第 1 步的源 4——把成品和踩坑写回自媒体选题池，同时把观众反馈记进 `开发选题池.md` 的"待定"区，作为下一轮灵感源。

---

## 输出文档：开发选题池.md

位置：`02 Areas/内容创作/开发选题/开发选题池.md`。不存在则用 `assets/selection-pool-template.md` 创建。

- 状态标记：`🔍 候选` / `✅ 已拍板` / `⏳ 开发中` / `📦 已完成→变内容` / `💤 待定`
- 每条记录：名字、总分、灵感来源笔记、三条门槛命中情况、状态、日期
- **维护纪律：只追加不删除。**没被选中的候选转为 `💤 待定` 保留，以后条件变了还能捡回来；已完成的划掉并记录产出了哪条内容。

## 常见卡点与处置

| 卡点 | 处置 |
|---|---|
| 找不到 Obsidian 库 | 问一次路径，记住，别重复问 |
| 库里素材太少，凑不够 3 个候选 | 直接转向源 2（用户的麻烦）+ 源 3（市场），并说明"这轮素材偏少，先从市场角度给你几个" |
| 候选和选题池里旧条目重复 | 第 0 步就该拦住；漏了就在卡片里标注"这是 X 的升级版"，说清楚差别 |
| 用户想直接开发，跳过选题 | 尊重他，跳到第 5 步交棒即可，但仍把这个选题补记进选题池 |
| 用户丢来一堆现成想法 | 从第 2 步开始，跳过喂料 |
| 用户说"接着上次的" | 读选题池，从 `💤 待定` / `🔍 候选` 里重新排序，不用重采 |
| 一个候选写得越来越大 | 立刻拆：MVP 留下，其余进选题池"以后再做" |

## 快速模式

用户说"快点""简单点""就给我三个"时：跳过第 0 步的动向扫描和源 3 联网搜索，只读选题池 + Obsidian 素材，直接给 3 个候选，卡片精简为「做什么 / 解决什么麻烦 / MVP 边界 / 内容钩子 / 反对意见」五行。
